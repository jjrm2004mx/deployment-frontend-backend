01 · Conceptos BaseModel Garden NO es un modelo: es un catálogo

Punto clave

  • "Model Garden" NO es un modelo de Gemini
  • Model Garden es el "catálogo/repositorio" donde Google publica modelos listos
💡
Sentencia para memorizar:
"Model Garden contiene a Gemini, pero no es Gemini."

Si lo llevamos a un lenguaje de plataforma:

  • Model Garden = inventario de modelos
  • Vertex AI = plataforma/infraestructura para operar esos modelos
  • Gemini = familia específica dentro del inventario

02 · AnalogíasLa analogía rápida (muy útil) y su extensión

Analogía base

  • Gemini: un tipo de planta (familia de modelos)
  • Gemini Pro: una especie específica (un modelo concreto dentro de esa familia)
  • Model Garden: el jardín botánico (catálogo de modelos)
  • Vertex AI: el invernadero + herramientas (donde los operas)

Extensión para embeddings

"No todo Gemini conversa: algunos solo hacen raíces (embeddings)."

  • Un modelo de embeddings convierte texto en "raíces" (vectores numéricos)
  • No genera texto conversacional
🎯
Frase memorizable:

"No todo lo que está en el Model Garden es Gemini, y no todo Gemini sirve para conversar: algunos solo hacen raíces (embeddings)."

04 · Diferenciasgemini-embedding-001 vs text-embedding-004 (sin confusión)

gemini-embedding-001

  • Es un modelo de embeddings
  • Pertenece a la "familia Gemini" (misma marca/familia)
  • Su función: texto → vector (no conversación)

text-embedding-004

  • Es un modelo de embeddings
  • NO es Gemini (es otra familia de embeddings dentro del jardín)
  • Su función: texto → vector
💡
Consejo:

En tu arquitectura, ambos cumplen el rol "embedding model".
Tu decisión suele depender de:
(a) calidad en tu dominio
(b) costo/latencia
(c) compatibilidad y estándares del equipo

05 · Casos de UsoMapa de decisión (qué rama usar según caso de negocio)

🎯
Regla mental de oro:

¿Lenguaje o razonamiento? → Gemini
¿Vectores / similitud semántica? → Embeddings
¿Imagen? → Vision
¿Voz? → Speech
¿Código? → Gemini (Code)
¿Predicción numérica? → ML especializado
¿Control total / auditoría / evitar lock-in? → Open-source curated

1) Gemini (LLM multimodal)

Usa cuando: conversación, generación, resumen, clasificación en lenguaje natural, razonamiento, multimodalidad.

  • Ultra: razonamiento máximo (casos críticos, complejos)
  • Pro: balance costo/capacidad (chatbots, apps, productividad)
  • Nano: edge/on-device (privacidad, baja latencia local)
  • gemini-embedding-001: cuando lo que necesitas es embeddings (texto→vector)

2) Text Embedding Models

Usa cuando: RAG, búsqueda semántica, similitud, clustering semántico, indexación.

  • text-embedding-004: opción moderna para producción
  • text-embedding-003: compatibilidad/transición
  • legacy: sistemas antiguos

3) Vision Models

Usa cuando: el input principal es imagen/documento visual.

  • Captioning: describir imágenes
  • Classification: categorizar imágenes
  • Detection: encontrar objetos
  • OCR/Document AI: extraer texto/estructura de documentos escaneados
  • Vision multimodal (Gemini): razonamiento sobre la imagen (no solo extracción)

4) Speech / Audio Models

Usa cuando: voz/audio es input o output.

  • STT: transcribir llamadas/reuniones
  • TTS: generar voz para asistentes
  • Audio Translation: traducir audio
  • Audio understanding (Gemini): análisis inteligente de la conversación/audio

5) Code Models

Usa cuando: el dominio es código.

  • Generación/entendimiento: típicamente Gemini Pro/Ultra
  • Autocompletado local: Nano si aplica
  • Reasoning profundo: Ultra

6) Specialized ML Models

Usa cuando: el problema es numérico/predictivo con datos estructurados.

  • Tabular: churn, scoring, riesgo con variables estructuradas
  • Forecasting/Time Series: demanda, tendencia, capacity
  • Classification: fraude, riesgos, etiquetas
  • Recommendation: personalización
  • Custom-trained: casos propios (con tu data y target)

7) Open-source curated models

Usa cuando: quieres control, transparencia, regulación, auditoría o evitar lock-in.

  • Validados: cumplimiento
  • Optimizados GCP: operación eficiente
  • Hugging Face: ecosistema abierto
  • Fine-tuning controlado: especialización fuerte/propia

06 · ImplementaciónCómo se usa Gemini desde Vertex AI para embeddings (mental model)

El flujo conceptual

Texto 
  → Embedding Model 
  → Vector (lista de floats) 
  → almacenamiento/índice 
  → Consulta semántica 
  → (opcional) RAG con un LLM

CASO A: Búsqueda semántica

  • Generas embedding de documentos (offline / batch)
  • Indexas los vectores (Vector Search o tu DB vectorial)
  • En runtime: embedding de la consulta → nearest neighbors → resultados

CASO B: RAG (Retrieval-Augmented Generation)

Igual que búsqueda semántica, pero después:

  • Recuperas top-k fragmentos (chunks)
  • Se los pasas al LLM (Gemini Pro/Ultra) como contexto
  • El LLM responde apoyado en esos fragmentos

Puntos de producción (los que más importan)

  1. Chunking: dividir documentos en fragmentos coherentes
  2. Metadata: docId, sección, fecha, fuente, permisos, etc.
  3. Versionado del modelo de embeddings: no mezclar embeddings de diferentes modelos
  4. Estrategia de re-embedding: si cambias de modelo, planifica recalcular vectores
  5. Métrica consistente: cosine/dot-product acorde al índice que uses

07 · ParámetrosTemperatura (dónde encaja)

La temperatura es un parámetro de muestreo en generación (no en embeddings).

  • Temperatura baja (≈0): respuestas más deterministas y conservadoras
  • Temperatura alta (≈1+): respuestas más variadas/creativas, pero más riesgo de desviarse o inventar
💡
Regla práctica:

• Para RAG / respuestas "de negocio": temperatura baja
• Para ideación creativa: temperatura media/alta
