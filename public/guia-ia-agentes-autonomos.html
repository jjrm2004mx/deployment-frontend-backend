01 · FundamentosClawdbot: Qué es técnicamente

Clawd es un asistente personal que puedes ejecutar localmente o a través de APIs de modelos y acceder a él tan fácilmente como desde tu teléfono. Pero, ¿qué es realmente?

🔧
En su núcleo: Clawdbot es una aplicación CLI escrita en TypeScript. No es Python, ni Next.js, ni una aplicación web.

Es un proceso que:

  • Se ejecuta en tu máquina y expone un gateway server para manejar conexiones de canales (Telegram, WhatsApp, Slack, etc.)
  • Realiza llamadas a APIs de LLM (Anthropic, OpenAI, modelos locales, etc.)
  • Ejecuta herramientas localmente
  • Hace prácticamente lo que tú le permitas hacer en tu computadora

¿Por qué importa entender esto?

Entender cómo funciona Clawd "por debajo del capó" permite comprender mejor el sistema y sus capacidades, y sobre todo, entender en qué es bueno y en qué es malo.

🧠
Lección para ingenieros de IA: Esto comenzó como una curiosidad personal sobre cómo Clawd maneja su memoria y qué tan confiable es. La respuesta está en la arquitectura.

03 · GatewayGateway Server y serialización por lanes

El Gateway Server es el corazón de Clawd. Actúa como coordinador de tareas y sesiones, manejando múltiples solicitudes superpuestas.

Sistema de Lanes

Para serializar las operaciones, Clawd usa una cola de comandos basada en "lanes":

  • Cada sesión tiene su propio lane dedicado
  • Las tareas de bajo riesgo y paralelizables pueden ejecutarse en lanes paralelos (ej: cron jobs)
  • Esto contrasta con el típico uso caótico de async/await
🎯
Principio clave:

"Serial por defecto, paralelo solo de forma explícita"

¿Por qué importa?

El exceso de paralelización reduce la confiabilidad y genera enormes pesadillas de depuración. Este mismo principio se menciona en el artículo de Cognition: "Don't build multi-agents".

⚠️
Problema común: Un setup async simple por agente termina generando logs ilegibles y, si comparten estado, las condiciones de carrera se vuelven un problema constante.

Cambio de modelo mental

Un lane es una abstracción sobre colas, donde la serialización es la arquitectura por defecto, no un parche posterior. El modelo mental cambia de:

  • Antes: "¿Qué necesito bloquear?"
  • Después: "¿Qué es seguro paralelizar?"

Como desarrollador, escribes el código normalmente y la cola se encarga de los problemas de concurrencia.

04 · Agent RunnerAgent Runner y bucle agéntico

Aquí es donde entra la IA de verdad.

Responsabilidades del Agent Runner

  1. Decide qué modelo usar
  2. Selecciona la API key disponible (si falla, marca el perfil en cooldown y prueba el siguiente)
  3. Hace fallback a otro modelo si el principal falla
  4. Construye dinámicamente el system prompt con herramientas, habilidades y memoria disponibles
  5. Añade el historial de sesión (desde un archivo .jsonl)

Context Window Guard

Antes de la llamada al LLM, pasa por un context window guard que verifica que haya espacio suficiente en el contexto:

  • Si el contexto está casi lleno → se compacta (resumen)
  • O falla de manera controlada

Llamada a la API del LLM

  • Transmite la respuesta por streaming
  • Abstrae las diferencias entre proveedores
  • Puede solicitar extended thinking si el modelo lo soporta

El bucle agéntico (la "magia")

🔄 Ciclo de herramientas

Si el LLM devuelve una llamada a herramienta:

1. Clawd la ejecuta localmente

2. Añade los resultados a la conversación

3. Vuelve a llamar al LLM

4. Repite hasta texto final o máximo de turnos (default: 20)

✨
Computer Use: Aquí es donde ocurre la magia. El agente puede usar tu computadora como lo haría un humano.

05 · MemoriaSistema de memoria híbrido

Sin un sistema de memoria adecuado, un asistente de IA es tan bueno como un pez dorado. Clawd maneja la memoria mediante dos sistemas:

1. Transcripciones de sesión en JSONL

La sesión se persiste en un archivo JSONL, donde cada línea es un objeto JSON con:

  • Mensajes del usuario
  • Llamadas a herramientas
  • Resultados
  • Respuestas

Así es como Clawd "recuerda" (memoria basada en sesión).

2. Archivos de memoria en Markdown

Ubicados en MEMORY.md o en la carpeta memory/. Los archivos Markdown son generados por el propio agente usando una herramienta estándar de escritura de archivos. No existe una API especial para "guardar memoria".

Búsqueda híbrida

Estrategia de búsqueda

Tipo Tecnología Ventaja
Vector search SQLite Encuentra coincidencias semánticas ("auth issues" ≈ "authentication bug")
Keyword search FTS5 (extensión SQLite) Coincidencias exactas, rápidas y precisas
Embeddings Configurable Proveedor a elección del usuario

Smart Syncing

Se activa cuando el file watcher detecta cambios. Al iniciar una nueva conversación, un hook toma la conversación previa y escribe un resumen en Markdown.

⚠️
Limitación importante: El sistema de memoria está implementado como memoria basada en flujos de trabajo.

No hay:
• Fusión de memorias
• Compresión semanal o mensual
• "Curva de olvido"

La memoria persiste indefinidamente y los recuerdos antiguos tienen prácticamente el mismo peso.

06 · Computer UseLas garras de Clawd: uso de tu computadora

Este es uno de los moats (ventajas defensivas) de Clawd: le das una computadora y la usa.

Herramienta exec

Clawd otorga acceso significativo al sistema (bajo tu propio riesgo) usando una herramienta exec para ejecutar comandos en:

  • Sandbox (por defecto, dentro de Docker)
  • Directamente en la máquina host
  • Dispositivos remotos

Herramientas incluidas

Categoría Herramientas
Sistema de archivos Leer, escribir, editar archivos
Navegador Basada en Playwright con semantic snapshots
Procesos Ejecución en background, kill de procesos, etc.
Shell Comandos arbitrarios (con permisos)
💡
Filosofía: Funciona como esperarías. La idea es ofrecer tanta autonomía como el usuario esté dispuesto a permitir.

07 · SeguridadSeguridad y Semantic Snapshots

Modelo de seguridad (¿o la falta de ella?) 😵

Similar a Claude Code, existe una allowlist de comandos:

  • Permitir una vez
  • Permitir siempre
  • Denegar

Comandos preaprobados

Los comandos considerados seguros vienen preaprobados:

jq, grep, cut, sort, uniq, head, tail, tr, wc

Las construcciones peligrosas de shell están bloqueadas por defecto.

Navegador: Semantic Snapshots

La herramienta de navegador no usa principalmente capturas de pantalla, sino semantic snapshots.

Estos snapshots son representaciones textuales del árbol de accesibilidad (ARIA) de la página.

¿Por qué semantic snapshots?

Aspecto Captura de pantalla Semantic Snapshot
Tamaño ~5 MB < 50 KB
Coste de tokens Muy alto (imágenes) Muchísimo menor
Naturaleza Visual Estructural (ARIA tree)
💡
Insight clave: Navegar no es necesariamente una tarea visual. El árbol de accesibilidad contiene la información semántica que el agente necesita.

08 · EvaluaciónValidación técnica y evaluación

✅ Lo que es técnicamente correcto

Aspecto Evaluación
Clawdbot como CLI en TypeScript ✔️ Totalmente plausible y coherente
Arquitectura gateway + adapters + agent runner ✔️ Patrón estándar y bien diseñado
Serialización por defecto con colas/lane ✔️ Excelente decisión de ingeniería
Uso de JSONL para sesiones ✔️ Muy común y efectivo
Memoria en Markdown + vector search + FTS5 ✔️ Diseño sólido y pragmático
Uso de ARIA / accessibility tree para navegación ✔️ Estado del arte en agentes

⚠️ Matices importantes a aclarar

Aspecto Matiz
"No hay curva de olvido" Es cierto funcionalmente, pero implica degradación semántica a largo plazo si la memoria crece demasiado
"Extended thinking" Depende totalmente del proveedor del modelo. No es una capacidad universal ni garantizada
Seguridad El modelo confía fuertemente en el usuario. No es "inseguro", pero no es zero-trust

🧠 Evaluación global

Desde un punto de vista de arquitectura de agentes, Clawd:

  • Está bien diseñado
  • Prioriza confiabilidad sobre hype
  • Sacrifica automatismos complejos (olvido, fusión) por simplicidad controlable
  • Es ideal para ingenieros, no para usuarios casuales
🎯
Veredicto: Arquitectura pragmática, honesta sobre sus limitaciones, y optimizada para desarrolladores que quieren control total sobre su agente.

09 · Claude Code¿Qué es Claude Code técnicamente?

Claude Code NO es un chatbot. Es un agente de desarrollo orientado a CLI, diseñado para vivir dentro del entorno del desarrollador.

🔧
Definición técnica: Claude Code es un runtime de agente ejecutado como CLI local, con acceso controlado a filesystem, shell y herramientas externas, orquestado por un LLM (Claude), con política explícita de permisos.

Lo que SÍ es

  • Un runtime de agente
  • Ejecutado como CLI local
  • Con acceso controlado a: filesystem, shell, herramientas externas
  • Orquestado por un LLM (Claude)
  • Con política explícita de permisos

Lo que NO es

  • Una app web
  • Un framework genérico
  • Un sistema multiagente distribuido
🧠
Modelo mental: Es un "AI pair programmer con capacidad de actuar". No es "un chat bonito"; es un runtime con contexto del proyecto, herramientas reales y una capa de control de permisos para acciones riesgosas.

10 · ArquitecturaClaude Code: Arquitectura y flujo de ejecución

ARQUITECTURA CLAUDE CODE

User (CLI Prompt)
        ↓
┌─────────────────────────┐
│ Context Loader          │ ← repo, files, diffs, logs, tests
│ (reconstruye contexto)  │
└───────────┬─────────────┘
            ↓
┌─────────────────────────┐
│ Agent Core              │ ← Claude Model
│ (razona + decide)       │   NO usa agentes separados
└───────────┬─────────────┘
            ↓
┌─────────────────────────┐
│ Tool Executor           │
│   ├─ read_file          │
│   ├─ edit_file          │
│   ├─ bash / shell       │
│   ├─ git diff           │
│   └─ npm test, etc.     │
└───────────┬─────────────┘
            ↓
┌─────────────────────────┐
│ Permission Gate         │ ← allow once / always / deny
└───────────┬─────────────┘
            ↓
Result / Diff / Output

Flujo detallado: ¿Qué pasa cuando le pides algo?

1. Input / Context Assembly

Claude Code no parte solo del prompt. Primero reconstruye el contexto real de trabajo:

• Estructura del repositorio • Archivos relevantes • Estado actual (diff, errores, tests) • Salida de comandos previos

👉 Esto elimina uno de los mayores problemas de los LLMs: razonar sin evidencia.

2. Planeación implícita (NO multiagente)

Claude Code NO usa agentes separados (Planner, Executor, Reviewer).

El modelo: razona → decide → actúa

Todo dentro de un solo loop controlado.

👉 Diseño conservador pero extremadamente estable.

3. Tool Execution Loop

Claude Code entra en un loop tipo:

THINK → TOOL → OBSERVE → THINK → TOOL → FINAL

Cada resultado se devuelve al modelo y queda anclado a hechos reales.

4. Control de concurrencia (implícito)

A diferencia de Clawd (lanes explícitos), Claude Code:

• Ejecuta una acción crítica a la vez • Evita paralelismo agresivo • Prioriza orden + trazabilidad

👉 Filosofía compartida: "Serial por defecto, paralelo solo si es inevitable"

11 · MemoriaClaude Code: Memoria y herramientas

❌ Lo que NO hace

  • No guarda memoria personal persistente
  • No escribe diarios
  • No tiene "recuerdos humanos"

✅ Lo que SÍ hace (mucho mejor)

Claude Code usa memoria basada en artefactos reales:

Artefacto Uso como memoria
Código fuente Estado actual del proyecto
Documentación Contexto de negocio y técnico
Tests Especificaciones ejecutables
Logs Evidencia de comportamiento
Commits Historial de decisiones
Diffs Cambios en progreso
💡
Ventaja enorme: Su "memoria" es el estado del proyecto, no recuerdos abstractos.

Esto significa: menos alucinaciones, más reproducibilidad, más auditabilidad.

Herramientas típicas integradas

  • Filesystem: leer/escribir/editar archivos
  • Shell/Bash: ejecutar utilidades del sistema (linters, tests, git, etc.)
  • WebFetch / navegación: según configuración
  • MCP (Model Context Protocol): conectar fuentes externas (Drive, Slack, Figma, etc.)
📖
Lectura clave: El agente "no adivina"; usa herramientas para obtener hechos (output de tests, grep, logs) y luego decide.

12 · SeguridadClaude Code: Seguridad y evaluación

Permission Gate

Claude Code introduce un sistema de permisos por herramientas:

  • Allow once — permitir esta vez
  • Allow always — permitir siempre
  • Deny — denegar

Allowlist de comandos seguros

Comandos preaprobados:

grep, jq, cut, sort, uniq, head, tail, tr, wc

Bloqueo activo

  • Pipes peligrosos
  • Redirecciones riesgosas
  • Comandos destructivos
⚠️
Importante: La seguridad no es automática, depende del usuario. Los permisos son la "última línea de defensa".

✅ ¿En qué es MUY bueno Claude Code?

  • Refactors complejos con evidencia
  • Corrección de bugs con pruebas reales
  • Automatización de tareas repetitivas
  • Trabajo con repos grandes
  • Cambios multiarchivo coherentes

❌ ¿En qué es MALO o riesgoso?

  • Producción sin sandbox
  • Permisos excesivos
  • Proyectos sin tests
  • Autonomía sin supervisión
🎯
Resumen conceptual:

Claude Code es: 🧠 Un ingeniero junior incansable, 🛠️ con acceso real al sistema, 📜 que solo confía en evidencia, ⚠️ y que puede romper cosas si lo dejas solo.

13 · OpenAI Agents¿Qué es OpenAI Agents técnicamente?

OpenAI Agents NO es un producto, es un framework de orquestación. Te da primitives, SDK, tracing y guardrails. Tú construyes el agente.

🏗️
Definición: OpenAI Agents es un enfoque/stack para construir workflows agénticos: un modelo que ejecuta tareas usando herramientas, puede hacer handoffs a subagentes especializados y deja trazas completas de lo ocurrido.

El Agents SDK (Python) te da primitivas para:

  • Definir agentes
  • Definir herramientas
  • Definir handoffs (agente A → agente B)
  • Definir guardrails (validaciones / límites)
  • Ejecutar orquestación
  • Observar todo mediante tracing

Diferencia clave respecto a "un chat"

  • Tú defines el runtime de herramientas y el control (timeouts, retries, permisos)
  • Puedes debuggear el comportamiento como si fuera un sistema distribuido (traces)

Flujo "estándar" de un agente

  1. Run Initialization: input, contexto inicial, configuración de límites
  2. Reasoning → Tool Invocation: decide si necesita datos, llama herramientas definidas por TI
  3. Tool Execution (tu código): funciones que viven en tu backend, acceden a DB, APIs, colas
  4. Handoff (opcional): delegación a otro agente especializado
  5. Guardrail checks: validaciones, policy, formato, límites
  6. Output final
  7. Tracing de absolutamente todo
🔒
Seguridad perimetral: OpenAI no ejecuta nada directamente. Las tools son funciones que TÚ defines y controlas.

15 · MemoriaOpenAI Agents: Memoria y guardrails

Memoria (la parte crítica)

OpenAI Agents no te obliga a una sola estrategia; te da el "esqueleto" para implementar memoria como tú decidas:

Opciones de memoria

Tipo Implementación Uso típico
Conversacional corta Historial que pasas al agente Contexto inmediato
Memoria larga Herramienta (RAG: vector DB, SQL) Conocimiento persistente
Session stores Redis (opción en SDK) Estado de sesión
💡
Interpretación práctica: OpenAI te da mejores "ganchos" para hacer memoria enterprise (con gobernanza), porque todo puede quedar como herramientas + trazas + stores, en vez de "escribo markdown y ya".

Guardrails: el verdadero diferenciador

  • Tools: tú las defines (funciones) y controlas el perímetro
  • Guardrails: puedes imponer límites (formato, validación, compliance) como parte del flujo
  • Handoffs: separar responsabilidades (Planner, DB expert, Writer) sin caer en caos, porque queda trazado

Handoffs: multiagente controlado

Aquí sí hay multiagente, pero controlado:

  • Cada agente tiene rol definido
  • Tools específicas por agente
  • Límites claros

👉 Esto evita el "spaghetti agent".

16 · ObservabilidadOpenAI Agents: Tracing y evaluación

Tracing: la mayor fortaleza

OpenAI Agents incluye tracing de todo:

  • LLM calls
  • Tool calls
  • Handoffs
  • Errores
  • Tiempos
  • Eventos custom
📊
Esto permite: debugging real, métricas, SLAs, postmortems.
👉 Clawd y Claude Code no llegan a este nivel de observabilidad.

Seguridad: diseño enterprise

  • Ninguna tool hace nada sin tu código
  • Ningún acceso implícito
  • Todo pasa por validaciones

👉 Seguridad por diseño, no por confianza.

✅ ¿En qué es MUY bueno OpenAI Agents?

  • Sistemas productivos
  • Flujos complejos multi-herramienta
  • Integraciones enterprise
  • Observabilidad completa
  • Escalabilidad
  • Compliance

❌ ¿En qué es malo?

  • No es plug & play
  • Requiere diseño previo
  • Overkill para tareas simples
🏗️
Resumen conceptual:

OpenAI Agents es: 🏗️ Un framework de construcción, 🧩 para arquitectos, 📊 obsesionado con trazabilidad, 🛡️ diseñado para producción.
