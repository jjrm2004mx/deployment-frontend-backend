00 · FundamentosConceptos básicos: Tokens y Solicitudes

Antes de entrar en el entrenamiento de LLMs, es esencial comprender dos conceptos fundamentales que rigen cómo funcionan estos modelos: los tokens y las solicitudes.

¿Qué es un Token?

Un token es la unidad más pequeña en la que se divide el texto para que el modelo pueda procesarlo. A diferencia de lo que pueda parecer, un token no es necesariamente una palabra.

Ejemplos de tokenización

Texto Tokens Cantidad
Hello "Hello" 1 token
uncommon "un", "common" 2 tokens
🚀 emoji "🚀", " ", "emoji" 3 tokens
The quick brown fox "The", " quick", " brown", " fox" 4 tokens
Información "Infor", "mación" 2 tokens (a menudo más en idiomas no inglés)
💡
Regla práctica: En inglés, 1 token ≈ 4 caracteres. Palabras comunes = 1 token, palabras raras o caracteres especiales = 2-3 tokens. En otros idiomas (español, chino, etc.) es más.

¿Qué es una Solicitud (Prompt)?

Una solicitud (o prompt) es el texto que le envías al LLM para indicarle qué queremos que haga. La forma en que la escribas determina completamente la calidad y el tipo de respuesta.

Ejemplos de solicitudes

  • Pobre: "escribe un cuento" → Respuesta vaga y sin estructura
  • Mejor: "escribe un cuento de fantasía para niños de 8 años, con un protagonista llamado Elena y un dragón amistoso, en 300 palabras" → Respuesta coherente y dirigida
  • Óptima: [instrucción clara] + [contexto] + [formato esperado] + [restricciones] → Respuesta profesional
🎯
Principio: Los LLMs responden mejor a solicitudes específicas y estructuradas.

Cuanto más detalle, contexto y claridad des, mejor será la respuesta.

Relación Tokens ↔ Costo y Velocidad

Los LLMs modernos (como GPT-4, Claude) cobran por número de tokens procesados, no por número de palabras. Por eso comprender tokens es esencial:

  • Entrada (Prompt): Costo por tokens en tu solicitud
  • Salida (Respuesta): Costo por tokens que genera el modelo
  • Velocidad: Más tokens = más tiempo de procesamiento
⚠️
Ventana de contexto: Cada modelo tiene un límite máximo de tokens que puede procesar en una solicitud (ej: GPT-4 = 128k tokens, Claude 3 = 200k tokens). Exceder este límite causa error.

01 · TextoLLMs para procesamiento de texto

Una de las aplicaciones más poderosas de los LLMs es el procesamiento y generación de texto. Desde resumir documentos hasta traducir idiomas, los LLMs ofrecen soluciones robustas para tareas textuales complejas.

Casos de uso principales

Tarea Descripción Casos prácticos
Generación de contenido Crear texto nuevo coherente y relevante a partir de instrucciones Copywriting, emails, artículos de blog, descripciones de productos
Summarización Extraer lo más importante de un documento largo Resúmenes de reportes, abstracts de papers, resumen de reuniones
Traducción Convertir texto de un idioma a otro manteniendo sentido Localización de software, documentos multiidioma, subtítulos
Clasificación de texto Categorizar texto según criterios (sentimiento, tema, spam, etc.) Análisis de sentimiento, detección de spam, categorización automática
Extracción de información Obtener datos estructurados de texto no estructurado Extracción de entidades, relaciones, información de documentos
Reescritura y mejora Editar texto para mejorar claridad, tono, longitud Corrección de estilo, simplificación de texto técnico, expansión/compresión
Análisis y búsqueda semántica Entender significado profundo y encontrar texto similar Búsqueda por similitud, clustering de documentos, detección de duplicados
Pregunta-respuesta (Q&A) Responder preguntas basadas en un contexto o conocimiento previo Chatbots de soporte, FAQ automatizado, búsqueda de respuestas en documentos

Herramientas y modelos recomendados

  • GPT-4 / GPT-4o (OpenAI): Mejor en calidad; caro pero versátil
  • Claude 3.5 Sonnet (Anthropic): Excelente relación calidad-precio; bueno en análisis largo
  • Llama 3 (Meta): Open-source; ejecutable localmente, buen rendimiento
  • Mistral 8x22B (Mistral AI): Modelo mixto de expertos; rápido y eficiente
  • Google Gemini: Bueno en multimodalidad e integración con Google Workspace

Trade-offs clave

Calidad vs Costo

Modelos grandes (GPT-4) ofrecen mejor calidad pero cuestan 10-30x más que modelos medianos. Para tareas simples, modelos más pequeños pueden ser suficientes y ahorrar mucho.

Contexto vs Privacidad

APIs cloud ofrecen acceso fácil pero envían tus datos a servidores remotos. Modelos locales garantizan privacidad pero requieren infraestructura.

Velocidad vs Precisión

Modelos rápidos (Mistral 7B) son ideales para aplicaciones con latencia crítica. Modelos lentos (GPT-4, Claude 3 Opus) ofrecen mejor precisión pero con mayor latencia.

💡
Consejo práctico: Para tareas de texto en producción, considera una estrategia híbrida: usa modelos rápidos pequeños por defecto (Llama 3.2 7B) y escala a modelos mayores solo cuando sea necesario.

02 · CódigoLLMs para desarrollo de software

Los LLMs son expertos en más de una docena de lenguajes de programación. Pueden ayudarte a compilar nuevas aplicaciones, mantener código existente y mejorar la calidad del código.

Tres áreas principales

Área Descripción Ejemplos
Compilación de aplicaciones Generar código nuevo a partir de especificaciones o bocetos Scaffolding de APIs, generación de boilerplate, creación de funciones completas
Mantenimiento de código Actualizar, refactorizar o debuggear código existente Migración de versiones, refactorización, eliminación de deuda técnica, debugging
Mejora de código Optimizar código según métricas específicas Aumento de seguridad, mejor logging, optimización de rendimiento, documentación

Lenguajes soportados

Los LLMs modernos soportan la mayoría de lenguajes populares: Python, JavaScript/TypeScript, Java, C#, C++, Go, Rust, SQL, PHP, Kotlin, Scala, y más.

Herramientas especializadas en código

  • GitHub Copilot (ChatGPT/Codex): Integración IDE, autocomplete en tiempo real
  • Claude Code (Anthropic): CLI local, acceso a filesystem y shell
  • GPT-4o (OpenAI): Conversacional, bueno para refactorings complejos
  • Codeium / Tabnine: Alternativas open-source a Copilot
  • Continue / Aider: Agentes de código locales con soporte de herramientas

Casos de uso reales

API Web desde cero

Prompt: "Genera una API REST en FastAPI con endpoints para CRUD de usuarios con autenticación JWT" → Resultado: código funcional listo para usar (estructura, validaciones, errores)

Migración de tecnología

Prompt: "Convierte este código Node.js a Python FastAPI manteniendo la lógica" → Resultado: código equivalente en el nuevo stack, con matices idiosomáticos

Generación de tests

Prompt: "Genera tests unitarios con pytest para la clase UserService" → Resultado: suite de tests que cubre casos principales y edge cases

⚠️
Advertencia importante: El código generado por LLMs puede tener:
• Errores lógicos o de sintaxis (revisa siempre)
• Vulnerabilidades de seguridad (valida con herramientas de análisis)
• Dependencias subóptimas (verifica licencias y compatibilidad)

Regla de oro: Usa LLMs para acelerar, pero revisa siempre con un humano experto.

03 · ImágenesLLMs para procesamiento de imágenes

Los LLMs modernos pueden crear, editar y modificar imágenes de alta calidad. Desde generación artística hasta edición precisa, estos modelos abren nuevas posibilidades creativas.

Tres capacidades principales

Capacidad Descripción Ejemplos
Generación de imágenes Crear imágenes originales a partir de descripciones textuales detalladas Diseño de productos, ilustraciones, arte conceptual, marketing visual
Edición de imágenes Modificar imágenes existentes: cambiar estilo, agregar/remover elementos, cambiar fondo Retoque de fotografía, cambio de escena, ajuste de atributos, reemplazo de objetos
Variaciones de imágenes Generar múltiples versiones de una imagen con cambios controlados A/B testing visual, exploración de diseños, generación de thumbnails en diferentes estilos

Modelos principales

  • DALL-E 3 (OpenAI): Mejor en seguimiento de instrucciones, muy fotorealista
  • Midjourney: Excelente para arte, estilo único y coherencia visual
  • Stable Diffusion (open-source): Ejecutable localmente, bajo costo, comunidad activa
  • Flux (Black Forest Labs): Nueva generación, mejor calidad y velocidad
  • Google DeepDream / PaLM: Integración con ecosistema Google

Workflow típico

1. Generación con detalle extremo

Cuanto más específico sea tu prompt, mejor resultado. Incluye: estilo, iluminación, composición, atributos.

2. Iteración y refinamiento

Genera variaciones, selecciona la mejor, pide ajustes puntuales (agregar elemento, cambiar color, etc.)

3. Post-procesamiento humano

Usa Photoshop, Figma o herramientas de edición para los últimos toques de refinamiento.

Trade-offs clave

  • Costo: DALL-E y Midjourney cuestan $0.02-0.30 USD por imagen; Stable Diffusion local es gratis
  • Velocidad: Midjourney es lento (minutos); Stable Diffusion es rápido (segundos)
  • Control vs creatividad: DALL-E bueno para control preciso; Midjourney para libertad creativa
  • Derechos: Verifica licencias; algunos modelos exigen atribución, otros no
🎨
Tip práctico: Para proyectos comerciales, comienza con DALL-E 3 (buena calidad, API simple). Si necesitas más control o bajo costo, usa Stable Diffusion localmente. Para arte puro y creatividad sin límites, Midjourney sigue siendo el rey.

04 · DecisiónCuándo usar (y cuándo NO usar) LLMs

Los LLMs son herramientas poderosas, pero no son la solución para todo problema. Esta sección te ayuda a decidir cuándo es una buena idea usarlos y cuándo es mejor buscar alternativas.

✅ Casos ideales para LLMs

Caso de uso Por qué funciona bien Ejemplo
Generación de texto Es lo que los LLMs hacen mejor: predecir secuencias coherentes Copywriting, emails, artículos, summaries
Clasificación y análisis de sentimiento Pueden entender contexto complejo mejor que modelos simples Detección de spam, análisis de feedback de clientes
Traducción de idiomas Capturan semántica, no solo palabras clave Localización de productos, documentos multiidioma
Code generation y refactoring Entienden patrones de código y best practices Autocomplete, generación de tests, conversión de lenguajes
RAG (Retrieval + Generation) Combina recuperación precisa + generación fluida Chatbots sobre docs internos, Q&A técnico
Extracción de información Puede parsear documentos no estructurados Extracción de datos de facturas, contratos, reportes
Explicación y educación Adapta el nivel de detalle y simplicidad al usuario Tutoriales personalizados, explicación de conceptos complejos
Brainstorming y ideación Genera múltiples perspectivas rápidamente Nombres de productos, estrategias de marketing, temas de contenido

❌ Casos donde NO deberías usar LLMs

Caso problemático Por qué es riesgoso Alternativa recomendada
Aritmética y cálculos precisos Los LLMs no entienden matemáticas, solo simulan; cometen errores sistemáticos APIs de cálculo, Python, Excel
Decisiones críticas sin validación Pueden alucinar; riesgo de daño si se actúa sin verificar Procesos de aprobación humana, auditoría
Datos sensibles sin compliance Riesgo de data leakage; memorización de PII; regulaciones (GDPR, HIPAA) Modelos locales, on-prem, o APIs con garantías de privacidad
Tareas que exigen exactitud 100% Los LLMs tienen tasa de error inherente (hallucinations) Búsqueda de bases de datos, consultas SQL
Sistemas en tiempo real ultra-bajo latency Los LLMs son lentos (cientos de ms); no apto para trading HFT, juegos, etc. Modelos más pequeños, reglas heurísticas, búsqueda indexada
Tareas que solo requieren buscar hechos Usa un buscador (Google, Elastic); es más rápido y preciso que LLM Motores de búsqueda, bases de datos vectoriales (si es por similitud)
Información muy reciente (últimas horas) El conocimiento del LLM es estático; no actualiza en tiempo real APIs de noticias, web scraping, bases de datos en vivo

Matriz de decisión: ¿Qué modelo elegir?

Guía por escenario

Escenario Prioridad Opción recomendada
Máxima capacidad + presupuesto ilimitado Calidad > costo GPT-4 / Claude 3 Opus (cloud)
Buen balance calidad/costo Equilibrio GPT-4 Mini / Claude 3.5 Sonnet / Llama 3.1
Costo mínimo (presupuesto ajustado) Costo < calidad Llama 2 / Mistral 7B (local) o Grok (acceso gratuito)
Privacidad máxima (datos sensibles) Privacidad > todo Llama 3 / Mistral en servidor propio (on-prem)
Baja latencia (aplicaciones en tiempo real) Velocidad > capacidad Modelos pequeños (Phi 3, TinyLlama) locales, o destillación
Dominio especializado (medicina, ley, finanzas) Exactitud en dominio Modelo base fine-tuneado + RAG + guardrails

Trade-offs clave

🎯 Costo vs Capacidad

Modelos grandes (GPT-4, Claude Opus) son mejores pero 10-100x más caros. Para tareas sencillas, modelos pequeños baratos pueden ser suficientes.

Regla: Comienza con modelo pequeño; escala si no cumple.

⚡ Latencia vs Precisión

Modelos locales = baja latencia (50-200 ms) pero menor capacidad. Modelos cloud = latencia media (500 ms-2 s) pero mejor precisión.

Regla: Si necesitas respuesta en <100 ms, usa modelo local o reglas heurísticas.

🔒 Privacidad vs Rendimiento

Cloud APIs (OpenAI, Anthropic) son convenientes pero tus datos van a sus servidores. Modelos on-prem garantizan privacidad pero requieren infraestructura.

Regla: Para datos PII/sensibles, usa on-prem o proveedor con garantías legales.

Tres categorías de modelos generativos (ampliadas)

Clasificación por tipo de tarea

Categoría Descripción Ejemplos Casos de uso
Modelos de lenguaje natural (LLMs) Toman texto y generan respuestas textuales coherentes GPT-4, Claude, Llama, Mistral Chat, generación de contenido, traducción, código
Modelos de transformador generativos (GPT-style) Toman fragmentos de código o lenguaje natural y generan código GitHub Copilot, GPT-4 Code, CodeGen Code completion, refactoring, debug, generación de tests
Modelos de generación de imágenes Toman indicaciones textuales, imágenes base o ambas; crean imágenes nuevas DALL-E, Midjourney, Stable Diffusion, Flux Diseño, marketing, ilustración, edición de imágenes
Modelos multimodales Combinan texto, imagen, video y audio en un modelo único GPT-4o, Claude 3.5 Vision, Gemini 2.0 Análisis de documentos escaneados, asistente visual, video QA
Modelos de embeddings Convierten texto a vectores numéricos; no generan, clasifican por similitud text-embedding-3, ada, BGE RAG, búsqueda semántica, clustering, recomendaciones
🎯
Resumen de decisión:

1. ¿Es tarea de texto/generación? → LLM
2. ¿Necesitas código? → LLM code-optimizado
3. ¿Necesitas imagen? → Modelo de imagen
4. ¿Requiere exactitud 100%? → No uses LLM, usa búsqueda/cálculo directo
5. ¿Datos sensibles? → On-prem o garantías legales
6. ¿Tiempo real (<100 ms)? → Modelo local pequeño

05 · FundamentosEntrenamiento de LLM: Autosupervisado → SFT → RLHF

Visión de 3 etapas

  1. Preentrenamiento autosupervisado (Pretraining): el modelo aprende lenguaje a gran escala prediciendo la siguiente palabra/fragmento. Usa un corpus amplio y diverso. Resultado: modelo base con conocimiento general pero sin estar alineado.
  2. SFT (Supervised Fine-Tuning): se entrena con pares instrucción → respuesta de alta calidad para enseñar formato, estilo y cumplimiento de instrucciones. Resultado: modelo instruccional.
  3. RLHF (Reinforcement Learning from Human Feedback): se entrena un modelo de recompensa (RM) con preferencias humanas y luego se optimiza la política del LLM (p.ej., con PPO o DPO) para maximizar utilidad y seguridad. Resultado: modelo alineado.
💡
Modelo mental:

Pretraining = conocimiento · SFT = formato/obediencia · RLHF = conducta/valores.

Detalles operativos

  • Calidad de datos: limpieza, deduplicación, filtrado de toxicidad, licencias y curación.
  • Tokenización estable: define vocabulario y controla cambios entre fases.
  • Conjuntos de evaluación: automáticos y humanos para before/after en cada etapa.
  • Seguridad y cumplimiento: políticas de seguridad, guardrails y auditoría en todo el pipeline.
  • Observabilidad: monitoreo de calidad, sesgo, toxicidad, y drift post-despliegue.

Variantes modernas

  • DPO: optimiza con preferencias directas, simplificando la etapa de RM/PPO.
  • RLAIF: usa feedback de modelos alineados cuando el humano es costoso.
  • LoRA/PEFT: fine-tuning eficiente en parámetros para dominios/estilos específicos.
  • Distillation: transferir comportamiento de un modelo grande a uno más pequeño.

08 · MétricasMétricas de evaluación

Métricas automáticas

  • Perplexity: mide qué tan "sorprendido" está el modelo ante texto real; menor = mejor fluidez.
  • BLEU / ROUGE: similitud n-gram con referencias; útil en traducción y resumen.
  • Exact Match / F1: para QA y extracción de entidades.
  • Pass@k: tasa de éxito en generación de código (ej. HumanEval).
  • Toxicity score: clasifica contenido dañino (Perspective API, Detoxify).
  • Bias benchmarks: WinoBias, BBQ, RealToxicityPrompts.

Métricas humanas

  • Win-rate: % de veces que evaluadores prefieren respuesta A vs B.
  • Likert scale: puntuación 1-5 en utilidad, coherencia, seguridad.
  • Red-teaming: adversarios intentan romper políticas; mide robustez.

Escala típica (orden de magnitud)

Fase Tokens GPU-hours (A100)
Pretraining (7B) 1-2 T ~50 k
SFT 10-100 M ~500-2 k
RLHF 1-10 M comparaciones ~1-5 k
💡
Regla: combina métricas automáticas (velocidad) con evaluación humana (calidad real). Ninguna métrica sola es suficiente.

09 · HerramientasHerramientas y frameworks

Entrenamiento y fine-tuning

  • Hugging Face Transformers + TRL: SFT, RLHF/DPO out-of-the-box.
  • DeepSpeed / FSDP: paralelismo eficiente para modelos grandes.
  • Axolotl: wrapper para fine-tuning con LoRA/QLoRA.
  • LLaMA-Factory: framework unificado para SFT y RLHF.

Serving e inferencia

  • vLLM: alto throughput con PagedAttention.
  • TGI (Text Generation Inference): Hugging Face, optimizado para producción.
  • Ollama / LM Studio: ejecución local fácil.
  • TensorRT-LLM: NVIDIA, máxima optimización en GPUs.

Evaluación y observabilidad

  • LangSmith / LangFuse: trazabilidad de prompts y respuestas.
  • Weights & Biases: logging de experimentos y métricas.
  • Promptfoo: evals automatizados con aserciones.
  • Inspect AI (UK AISI): framework open-source para evals de seguridad.

RAG y orquestación

  • LangChain / LlamaIndex: pipelines de retrieval y agentes.
  • Pinecone / Weaviate / Qdrant: vector stores gestionados.
  • Chroma: vector store ligero para desarrollo.

10 · RiesgosRiesgos y mitigaciones

Matriz de riesgos

Riesgo Descripción Mitigación
Hallucination Genera información plausible pero falsa RAG con fuentes verificadas, temperatura baja, chain-of-thought, citas
Prompt injection Usuario malicioso manipula el prompt para cambiar comportamiento Separación de sistema/usuario, sanitización, guardrails de entrada
Jailbreak Evadir políticas de seguridad mediante prompts creativos RLHF robusto, Constitutional AI, red-teaming continuo, filtros de salida
Data leakage Modelo memoriza y filtra datos privados del entrenamiento Deduplicación, differential privacy, PII scrubbing, auditoría de outputs
Bias / toxicidad Respuestas sesgadas o dañinas hacia grupos Curación de datos, RLHF con criterios de equidad, benchmarks de sesgo
Drift de calidad Degradación con el tiempo o cambios de distribución Monitoreo continuo, evals periódicos, reentrenamiento planificado

Constitutional AI (variante reciente)

Enfoque de Anthropic donde el modelo se auto-critica y revisa sus respuestas según un conjunto de principios (constitución). Reduce dependencia de etiquetado humano masivo y mejora alineamiento con valores explícitos.

🛡️
Defensa en profundidad: ningún control único es suficiente. Combina RLHF + guardrails de entrada + filtros de salida + monitoreo + red-teaming.

11 · MaticesMatices críticos sobre capacidades del LLM

A menudo escuchamos afirmaciones tajantes sobre lo que los LLMs "pueden" o "no pueden" hacer. Aquí matizamos tres de las más comunes para comprender mejor cómo funcionan realmente.

1. Comprensión del lenguaje y matemáticas

❌ Declaración original (incompleta)

"Un LLM no entiende el lenguaje ni las matemáticas."

✅ Matización correcta

Un LLM no entiende el lenguaje ni las matemáticas como un humano, pero sí aprende patrones muy profundos que le permiten comportarse como si entendiera en muchos contextos.

💡
Por qué importa: Es cierto que a nivel de arquitectura, un LLM es un modelo de probabilidad sobre tokens sin "comprensión" semántica verdadera. Pero internamente aprende representaciones matemáticas tan sofisticadas de sintaxis, semántica y estructura que puede resolver problemas de matemáticas, escribir código, razonar lógicamente, etc. No es "verdadera" comprensión, pero es funcionalmente equivalente en muchos casos.

2. Modos de recuperación y escritura creativa

❌ Declaración original (incompleta)

"Un LLM no tiene modos independientes para la recuperación de información y la escritura creativa; simplemente predice el siguiente token más probable."

✅ Matización correcta

El LLM solo predice texto; los modos 'buscar información' vs 'ser creativo' son efectos de cómo lo condicionamos (prompting + herramientas externas).

💡
Por qué importa: Es correcto que el modelo base no distingue entre "buscar" y "crear"; solo predice tokens. Pero en sistemas modernos, esa separación sí emerge:

• Recuperación: la proporcionas vía RAG (le das contexto relevante)
• Creatividad: la controlas vía temperature y prompting

Así que aunque el modelo no tiene "modos", la arquitectura externa sí los implementa.

3. Antropomorfismo, emociones y ética

❌ Declaración original (incompleta)

"Un LLM no puede mostrar antropomorfismo ni comprender la ética. La salida del modelo es una combinación de datos de entrenamiento y prompts."

✅ Matización correcta

No tiene emociones ni ética propias; solo imita patrones lingüísticos de cortesía, emoción y razonamiento moral aprendidos de los datos y de su ajuste fino (RLHF).

💡
Por qué importa: Es crucial distinguir entre:

• Simulación: el modelo puede generar un texto que suena empático, respetuoso o ético
• Verdadero entendimiento: no tiene conciencia, intención ni valores propios

Esto no significa que los outputs sean "falsos"; significa que son artefactos de estadísticas de entrenamiento + RLHF, no expresiones de una mente sintética.

Síntesis

Capacidad ¿Realmente? Matiz
Comprende lenguaje No / Sí* Aprende patrones muy profundos, pero sin semanticidad real
Hace matemáticas Limitado Mejor con prompting de cadena de pensamiento (chain-of-thought)
Distingue modos No internamente Pero la arquitectura externa (RAG, prompting) sí los implementa
Tiene emociones No Solo simula patrones de cortesía/empatía vistos en entrenamiento
Tiene ética No inherente La ética viene de RLHF y guardrails, no de creencias genuinas
🎯
Conclusión: Los LLMs son herramientas extraordinariamente potentes, pero es crucial entender sus límites y no proyectar agencia o consciencia donde solo hay estadística.

Usa el contexto de RAG, diseña prompts claros y aplica RLHF para moldear comportamiento, pero siempre recuerda que el modelo no "entiende" en el sentido humano.

12 · EjemploEjemplo práctico: fine-tune en dominio médico

Contexto

Una organización de salud quiere un asistente que responda preguntas sobre guías clínicas internas. El modelo base es Llama 3 8B.

Pipeline aplicado

  1. Curación de datos: 50 k pares pregunta→respuesta extraídos de documentación clínica aprobada; revisión de médicos.
  2. SFT con LoRA: 3 épocas, lr=2e-4, rank=64. Entrenamiento: ~8 h en 2×A100.
  3. Evaluación interna: 500 preguntas de prueba; BLEU, F1 y revisión humana (3 médicos).
  4. RLHF ligero: 2 k comparaciones A/B con DPO para mejorar claridad y evitar respuestas fuera de alcance.
  5. Guardrails: el modelo rechaza preguntas de diagnóstico definitivo; siempre sugiere consultar profesional.
  6. Despliegue: vLLM detrás de API interna; logging con LangFuse; dashboard de toxicidad y drift.

Resultados

  • Win-rate vs modelo base: 78 % (evaluadores médicos).
  • Reducción de alucinaciones clínicas: –62 % (RAG + guardrails).
  • Latencia P95: 1.2 s (contexto 4 k tokens).
📋
Lección: en dominios regulados, la calidad del dataset y los guardrails importan más que el tamaño del modelo.
